1. Proje Özeti ve Ne Yapıyoruz?

MobilServisiniz, oto servis işletmelerinin günlük operasyonlarını dijitalleştiren bulut tabanlı bir yönetim sistemidir. Her oto servis (tenant) kendi müşterilerini, araçlarını, iş emirlerini, stokunu ve raporlarını bağımsız olarak yönetir.

İş Modeli (SaaS)

  • Her oto servise benzersiz bir servis kodu verilir (ör. OTO-IST).
  • Servis personeli mobil uygulama veya web panelden bu kod ile giriş yapar.
  • Veriler tamamen izole — bir servis başka servisin müşterisini veya raporunu göremez.
  • Aynı personel birden fazla serviste çalışabilir; girişte servis kodu hangi servise bağlanacağını belirler.

Mobil uygulama doğrudan veritabanına bağlanmaz; tüm işlemler API üzerinden yapılır. Admin paneli performans için doğrudan SQL Server'a bağlanır (Dapper). Her iki kanal da aynı veritabanını kullanır.

3. Multi-Tenant (Çok Kiracılı) Model

Tenant = Servis (Shop)

Her kayıtlı oto servis bir shops kaydıdır. Benzersiz alanlar:

  • tenant_code — Giriş kodu (OTO-IST, OTO-ANK…)
  • slug — URL tanımlayıcı
  • subscription_plan — trial / standard / premium

Veri İzolasyonu

Tüm iş verileri shop_id ile filtrelenir: müşteriler, araçlar, iş emirleri, stok, faturalar, ödemeler.

İki Tür "Müşteri" Kavramı

KavramAçıklamaSistemde
Tenant (Servis)Sistemi satın alan oto servis işletmesishops tablosu
End CustomerAraç sahibi, servise gelen kişicustomers tablosu (shop_id ile)
Önemli: Aynı araç sahibi farklı servislere gidebilir; ancak her serviste ayrı müşteri kaydı oluşur. Geçmiş servisler arası paylaşılmaz (KVKK ve tenant izolasyonu).

Personel — Çoklu Servis Desteği

Kullanıcı hesapları platform genelinde (users). shop_users tablosu ile bir kullanıcı birden fazla servise bağlanabilir. Girişte servis kodu hangi servise girileceğini belirler.

AlanÖrnekAçıklama

Telefon05551112233Kullanıcı telefon numarası
Şifre1234Demo ortamında tüm hesaplar

Doğrulama Akışı

  1. Servis kodu shops tablosunda aranır → servis adı önizlemesi gösterilir
  2. Telefon + şifre doğrulanır (SHA-256 hash)
  3. Kullanıcının o serviste shop_users üyeliği kontrol edilir
  4. JWT (mobil) veya cookie (admin) oluşturulur; içinde shop_id ve rol bilgisi
  5. Tüm sonraki istekler yalnızca o servisin verisini döner

10. Yapay Zeka — Ruhsat Okuma

  • Sağlayıcı: Google Gemini (gemini-2.5-flash)
  • Kullanım: Yeni araç kaydında ruhsat fotoğrafından otomatik okuma
  • Okunan alanlar: Plaka, marka, model, yıl, renk, yakıt tipi, şasi no
  • Girdi: Kamera veya galeriden fotoğraf (base64)
  • API anahtarı: EXPO_PUBLIC_GEMINI_API_KEY veya ai-config.ts
  • Anahtar yoksa: Uyarı gösterilir, alanlar elle doldurulabilir

12. Kurulum ve Çalıştırma

Veritabanı

sqlcmd -S SUNUCU -U kullanici -P sifre -i mobile/db/sqlserver/01_schema.sql
sqlcmd -S SUNUCU -U kullanici -P sifre -i mobile/db/sqlserver/02_seed.sql

API

cd api/OtoServis.Api
dotnet run --urls http://localhost:5280
→ Swagger: http://localhost:5280/swagger

Admin Panel

cd api/OtoServis.Admin
dotnet run --urls http://localhost:5281
→ Panel: http://localhost:5281

Mobil (Geliştirme)

cd mobile
npm install
npx expo start
→ Android emülatör API: http://10.0.2.2:5280

APK Build

cd mobile/android
./gradlew assembleRelease
→ app-release.apk

14. Gelecek Adımlar

  1. API'yi üretim sunucusuna deploy (5280 portu + firewall)
  2. Mobil APK'yı servis kodu girişi ile yeniden build
  3. Yeni servis kayıt ekranı (super-admin onboarding)
  4. Gemini API anahtarı yapılandırması
  5. HTTPS + güçlü JWT secret (üretim güvenliği)
  6. Abonelik planı zorunluluğu (trial / standard / premium)
  7. Franchise / zincir modeli (opsiyonel — ortak müşteri geçmişi)
